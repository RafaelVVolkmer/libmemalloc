# Engineering procedures

Record rationale and evidence with the engineering review procedure. The wider lifecycle model retains the adoption
status stated in each procedure. Existing checks and protected release operations retain their documented authority.

- [Specification issues](specifications.md): maintainer labels, SDD scope and PR closure.
- [Change and review](change.md): procedure catalog, SDD/TDD loop and adoption criteria.
- [Engineering review](decision-making.md): rationale, alternatives and verification evidence in issues and pull
  requests.
- [Verification](verification.md): scope, expected work, execution and evidence review.
- [Release](release.md): candidate identity, acceptance and protected publication.
- [Security](security.md): vulnerability handling, dependency changes and service ownership.

Use the [runbooks](../runbooks/README.md) for commands and [standards](../standards/README.md) for canonical rules.
